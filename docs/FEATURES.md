# Features

What the desktop app does today, by area. See the CHANGELOG for what changed in each release.

## Documents, pages and preview

- **Documents:** the Explorer lists Screenplays (labelled Episodes for a series project), Notes and Canvases, each with {+}, rename (pencil, double-click or right-click), delete (confirm; the last screenplay can't be deleted) and drag reorder. Outline, characters/locations list, stats, preview and export use the active screenplay; character and location pages aggregate across all screenplays; Statistics has an "All episodes" scope.
- **Full pages (tabs):** canvas cards (double-click a card or click it in the card list), notes, characters, locations, scenes, Project information, Project settings. Markdown editors have Write/Split/View and embed pictures by button, drag and drop or paste. Pictures are copied into `assets/` by main (`sf:asset:pick`, `sf:asset:add`) and displayed through the `sfasset://` protocol (allowed in the CSP `img-src`), only for projects opened this session. Canvas tiles show the card's first picture.
- **Live preview:** Ctrl+P, View menu or the tab-strip button. Industry layout on 8.5x11 sheets (same geometry as pdf-export), title page first, scene numbers, follows the cursor's scene, white or dark paper. Pagination is approximate. A speech broken by a page gets (MORE) at the bottom and NAME (CONT'D) on top of the next page; dual dialogue prints in two columns.
- **Title-page defaults (inheritance with override):** Project information holds project-level title-page values. A new screenplay/episode gets them written into its title page once, at creation. On export (PDF and .fountain) any key missing from the script's own title page is filled from the defaults; a key the script has always wins (even empty). The script page shows "Inherited from project: …" when it inherits keys. The key table lives in `src/backend/title-page.ts`.
- **Draft date:** the key stays `Draft date`. Project information uses a date picker (stored ISO). The value is filled **only when a script is created** (project default, else today), formatted locale-independently as "11 October 2026", and is never rewritten on save; afterwards it is plain text. On a `Draft date:` / `Date:` title-page line, autocomplete offers today and the project default.
- **Title-page highlighting:** keys crimson/bold, values normal, indented continuation lines dim; non-standard keys are dim with a dotted underline and a hover doc.
- **Project settings:** project type, export page size (US Letter / A4) and scene numbers (both honored by pdf-export), accent color (project-list swatch), autosave override, link to Project information.
- **Per-project editor settings** (Project settings → Writing, `ProjectEditorSettings` in `lib/project.ts`): script inspections (App setting / On / Off), target length for the act-length check (empty follows Settings, 0 is off here), live templates for this project (they win over the user's own and the built-ins), and a project dictionary for the spellchecker. They live in the project file, so they travel with it; absent keys follow Settings.
- **Title page parsing:** the title page must open with a known key, after which any `Key: value` line belongs to it; `contact info`, `tc` and `cc` are known keys.

## Look, entities and authorship

- App icon: `build/icon.{png,ico,icns}` used by the window, the macOS dock, and Forge (`packagerConfig.icon`, Squirrel `setupIcon`, deb/rpm `icon`). The titlebar uses the `SceneformMark` SVG.
- The window starts maximized. F11 toggles real fullscreen.
- Width-aware panels: when the sidebar, editor (and preview) and inspector don't fit, one panel closes. The panel the user just opened stays; otherwise the inspector closes first.
- Themes: Dark, Light and System, plus palettes (Catppuccin Mocha/Latte, Ayu Dark/Light, Nord) from `src/renderer/lib/themes.ts`, plus Custom CSS (Settings → UI).
- Project settings → Banner: an asset shown on the project screen (`ProjectSummary.banner`). Listed projects with a banner may serve it over `sfasset://`.
- Characters & locations: an "Add" button creates an entity before the script mentions it. These show as dashed "not in script yet".
- Inspector → Cast tab: who speaks in the current scene, with portrait, role, age and description.
- Character names in action lines are underlined. Ctrl/Cmd+click opens the character.
- Project information auto-fills from the script's title page, for known keys only, and never overwrites a value that is already set.
- Autocomplete: title-page keys in conventional order; character cues and (V.O.) / (O.S.) / (CONT'D); transitions; `.` reuses a scene heading; `@` mentions a character (it stays at line start as the force); `#` mid-line mentions a location or heading (`#` at line start is still a section).
- Spellcheck: `dictionaries/en_US-LARGE.txt` (languagetool) plus `dictionaries/screenwriting.txt` (community, open to PRs), the user dictionary in settings, and project names. Hover a flagged word for suggestions or to add it.
- Authorship (blame): every script line stores who last wrote it and when (`authorship.json` in the .sfp; the name is Settings → Editor → Your name). View → Authorship (Ctrl/Cmd+Alt+A) shows the gutter. Canvas cards carry createdBy/createdAt/editedBy/editedAt (moving or resizing doesn't count as an edit), and the card inspector shows them. Lines written before tracking show "—".
- `%%% … %%%` special pages: their own page in the preview and in the PDF, with text placed by `<[tl|tc|tr|cl|cc|cr|bl|bc|br]>…</[pos]>`.
- Dual dialogue (`^` on the second cue): the caret is dimmed in the editor and both speeches get a faint side rule; the preview and the PDF print the two speeches side by side.

## Writing tools, history and interop

- Scene → Add scene ID markers (or the palette) gives every scene a hidden `[[id:…]]` marker so its metadata follows it; outline drag runs it first when position-keyed details exist. Scenes that still lack one keep position-based metadata, and the inspector says so.
- `pdf-export.ts` ignores `filterSceneIds` and `filterCharacters` on purpose: the export dialog builds the reduced script renderer-side, and doing it twice would let the two drift. The PDF title page only prints title, credit, author, draft date and contact.
- Picture cards on the canvas: drop or paste pictures onto a canvas (or use the toolbar's Picture card) and each becomes a card of type `image` showing the whole picture, titled after the file; its body is the Markdown embed, so the card page can still add notes. Pictures are copied into `assets/` like any other.
- Unreferenced assets are never cleaned up. Scene metadata for scenes without `[[id:…]]` follows position.
- `*include: Title` (`lib/include.ts`): a line of its own that names another screenplay/episode of the project pulls it in, without its title page, for the live preview and every export (PDF, .fountain, .fdx), so a master script can be assembled from act or episode files. Includes nest up to 8 deep; a loop or an unknown title prints a `[[note]]` instead, and the editor flags an unknown title (Alt+Enter offers the close matches). The editor, outline, statistics and scene filter in Export see each file as written. Exporting all episodes into one PDF is otherwise not built.
- Writer's intuition (IntelliJ-style workflow, `src/renderer/editor/intentions.ts`):
  - Inspections underline craft problems: a cue that appears once and is one or two letters off a known name ("JOHM" → JOHN), a cue with no dialogue, a heading with no time of day, an action block that runs past ~4 printed lines, a speaker who continues after action without (CONT'D), a character's first action mention not in CAPS, a place spelled two ways across headings (it fixes to the common spelling), speeches over ~12 lines, empty scenes, a speech that is only a parenthetical (fix: write a line, or make it action: "Bob nods."), a parenthetical that is really action (more than four words, or stage business such as "crosses", "picks", "enters"; fix: move it out as action, adding NAME (CONT'D) when the speech goes on), a bracketed line with no speaker (fix: drop the brackets), scenes over ~3 pages, and, when Settings → Editor → Target length is set (0 = off, the default), acts (top-level `#` sections) that drift from their share of it by more than 15% or 5 pages (three acts: ¼ ½ ¼, otherwise even; an act that runs short is only flagged once a later act has pages). They skip the line you're typing on (Alt+Enter and the right-click menu still offer that line's fixes). While you type, existing marks follow the text and the full check re-runs 0.4 s after you pause (about 7 ms on a ~150-page script; the per-edit re-parse costs 15-30 ms). You can turn them off in Settings → Editor → Script inspections, which applies at once.
  - Alt+Enter on any line opens the fixes for that line's problems, then context actions. Action lines can become a heading, cue, transition, centered text, note or lyric. Headings can switch INT./EXT./INT./EXT., set the time of day, or be numbered. Cues can toggle (V.O.), (O.S.) or (CONT'D), toggle dual dialogue ^, open the character page, or become action. Dialogue can get a parenthetical above it or become a lyric. In the menu, use the arrows and Enter, or press 1-9.
  - Ctrl/Cmd+Shift+Up/Down (or Alt+Shift+PageUp/PageDown, or Scene → Move scene up/down, or the palette) moves the whole scene past its neighbour. Where a section line (# ACT TWO) is in the way, the scene hops over the section header and becomes the last scene of the previous section or the first of the next one. The binding has high precedence, so the default "select to document start/end" can no longer swallow it.
  - Alt+Shift+Up extends the selection word → line → block (cue plus dialogue) → scene → enclosing sections → script. Alt+Shift+Down steps back. Both are in the Edit menu too.
  - Ctrl/Cmd+W closes the current tab, like a browser (File → Close tab). The last screenplay tab stays open.
  - Find usages: Alt+F7 on a cue (or a cast name in the text), or Alt+Enter / right-click → Find usages, opens a docked tool window under the script listing every cue and mention across all screenplays as scene · snippet. Alt+F7 on a scene heading lists every scene at that location instead. Type in its filter box to narrow, Enter or click to jump, Esc or ✕ to close (`components/toolwindow.tsx`).
  - Problems (View → Problems, Ctrl/Cmd+6, or the palette): the same tool window lists every inspection hit in the active script, with scene number and line, warnings marked red.
  - Rename a character everywhere: Shift+F6 on a cue (or on a cast name in the text), or Alt+Enter → Rename. It changes every cue plus the name in action, dialogue, parentheticals, lyrics, notes and synopses, in ALL CAPS and Title Case, across all screenplays, and it moves the cast entry. Scene headings are left alone unless you tick "Also in scene headings" in the rename dialog; then "JOHN'S HOUSE" becomes "MIKE'S HOUSE" and that location's page moves with it. Each open script takes one undo (`src/renderer/lib/rename.ts`).
  - Live templates (`editor/templates.ts`): type an abbreviation alone on a line and press Tab (int, ext, ie, intn, extn, fi, fo, ct, dt, sct, fb, eofb, mont, eom, beat, the end, phone, dual), or press Ctrl/Cmd+J (Edit → Insert live template…, or the palette) for a filterable picker; text before the cursor that starts an abbreviation seeds the filter and is replaced. Templates have tab stops: `$1`, `$2`, … (or `${1:default}`, pre-filled and selected) are visited with Tab / Shift+Tab, `$0` is where the cursor ends (the end when absent), Esc leaves the fields. `int` now selects LOCATION, then DAY. Add your own in Settings → Editor → Live templates as `abbr = text`, `\n` starts a new line. Your own win over built-ins. Built on CodeMirror's snippet fields; the same stop number used twice is not mirrored (the editor has no multiple selections).
  - Right-click in the script opens a context menu (`editor/context-menu.ts`): spelling suggestions and "Add to dictionary" on a flagged word, Cut/Copy/Paste, Find usages / Rename / Go to the character's page on a cue or cast name, Go to location page on a scene heading, and the line's Alt+Enter actions. Right-click a tab for Close, Close others and Close tabs to the right.
  - Outline as a structure view: section lines (# ACT ONE, ## sequence) appear as headers with their page and minute totals, each scene shows its length in eighths ("1 3/8"), and the panel heading shows the script's total. Drag a scene onto another to move it there (`moveSceneToSpec`, one undo; section headers are hopped like Ctrl/Cmd+Shift+Up/Down). Scenes without an `[[id:…]]` marker keep position-based metadata, so a moved scene's colour/WIP stays with the position, as with the keyboard move.
  - Breadcrumbs above the script show script › sections › scene › speaker, and each one is clickable. Double Shift opens Search Everywhere (the palette). Alt+Up/Down already steps between scenes.
- Local history (File → Local history…, or the palette), like IntelliJ's: each save snapshots the screenplays and notes into the app's data folder (`userData/local-history/<hash of project path>/`). It's never stored inside the .sfp. A snapshot is taken at most every 3 minutes unless 400+ characters changed, only when something changed, and the newest 300 are kept. The dialog diffs any snapshot against the current text, unified or side by side (Now | Snapshot, with line numbers, changed lines paired; the choice is remembered), restores a screenplay or note (one undo when its tab is open, and it brings back deleted documents), restores a single scene ("Restore this scene" lists the snapshot's scenes that changed or were deleted since; scenes match by `[[id:…]]` marker, else by heading and occurrence; a deleted scene goes back after its old predecessor; one undo), and labels the current version ("Sent to producer"; the label field sits under the snapshot list, with the revision-colour picker and Mark changes since at the bottom left of the dialog). Code: `src/desktop/local-history.ts`, `components/history.tsx`, `lib/diff.ts`, `lib/scene-restore.ts`.
- Revision marks: in Local history, pick a snapshot (usually a labelled draft), choose a WGA revision colour (Blue, Pink, Yellow, Green, Goldenrod, Buff, Salmon, Cherry) and press "Mark changes since". Every line added or changed since then gets the colour bar and a margin asterisk, live as you type. The breadcrumb bar shows the active revision with an × to stop. The active revision (snapshot, colour) is remembered per project in the app settings (`activeRevisions`), so it comes back after a restart while that snapshot is still in Local History. PDF export doesn't print the asterisks yet (`editor/revisions.ts`).
- Final Draft interop (`src/shared/fdx.ts`, pure TS, unit-tested round trip):
  - Import: the project screen's Import accepts .fdx and converts it to Fountain. Headings (with numbers), action, cues, parentheticals, dialogue, dual dialogue, lyrics, transitions, shots, page breaks, acts, centred text and bold/italic/underline come across. The title page is read best-effort from FD's free paragraphs (see below).
  - Fade In: Import also accepts .fadein (a zip around Open Screenplay Format XML), read with the same element mapping. Tested against real files from Fade In 3.x and 5.x and the OSF SDK's 1.2 / 2.0 / 4.0 reference documents (`test/fixtures/interop/README.md`): all three spellings of the style attribute (`basestylename`, `baseStyleName`, `basestyle`), `dualdialogue="1"` on the first cue of a pair, `scene_number` / `number`, `pagebreakbefore`, paragraph notes (→ `[[note]]`) and synopses (→ `= synopsis`), and the title page from bookmarks (OSF 4) or `<info>` (OSF 1.2).
  - Title pages from FDX/OSF are read by alignment: the centred block gives Title, Credit, Author and Source; the side block gives Copyright, Draft date and Contact. FD page headers on the title page are ignored. FD script notes come across as `[[notes]]`.
  - Import into an open project: File → Import screenplay… (or the palette) takes a .fountain, .fdx or .fadein file and adds it as a new screenplay (episode in a series) named after the file, opened in a tab. The original file is left untouched.
  - Export: Export → Final Draft (.fdx), with the same elements in reverse. The Export dialog lists the three formats as described choices (PDF, Fountain, Final Draft); the options below follow the chosen format and the button names it. Project title-page defaults fill in what the script leaves out. Notes, synopses, boneyard and special pages aren't exported.
- Merge another copy (File → Merge another copy…, or the palette; `lib/merge.ts`): async collaboration without a server. Pick a collaborator's copy of the same project (.sfp); it is read-only (`sf:project:read-copy`). Screenplays get a three-way merge on the Fountain text. The common ancestor is rebuilt from the authorship stamps: lines with the same text, author and time in both copies predate the split, the newest such stamp is the split time, and every line stamped at or before it (or never stamped) on either side forms the base. Without shared stamps the base is the lines both copies have (a union merge). A region changed in one copy takes that copy's version; where both changed it, it goes line by line (a rewrite is "drop the old lines, insert the new after them"), and only where both insert or rewrite at the same spot are both versions kept between `[[MERGE CONFLICT: …]]` / `[[…and … wrote this…]]` / `[[END MERGE CONFLICT]]` notes, which the Problems window lists as warnings. Merged lines keep the stamps of the copy they came from. Notes merge the same way without stamps; canvases take new cards and, per card, the later `editedAt`; documents only the copy has are added; character/location/scene details only fill fields that are empty here. A confirm dialog summarises what comes in per document; on Merge the current version is labelled in Local history ("Before merging …"), the result is saved and the project reloads. Pictures inside the copy (`assets/`) aren't brought over. A deletion in one copy against an edit of the same line in the other keeps the edit.
